# Unity player builds

## Headless build and its memory
- Build headless: `Unity.exe -batchmode -nographics -quit -projectPath <full path> -buildTarget <target> -executeMethod <Class.Method> -logFile <project>/Logs/claude/<job>.log -desiredWorkerCount 1 -standbyWorkerCount 0` (own log and one import worker: `unity-cli-saha-notlari.md` › Headless editor). Always pass `-buildTarget`: without it the editor opens on the Library's last target, and a build method that switches target reimports first.
  - `-nographics`: no graphics device, ~0.3 GB less editor memory (2.81 → 2.53-2.56 GB), the same bundle. Not in a game that bakes GI (the manual: no GI baking with it).
- **Where an Android IL2CPP build peaks** (a project, 2026-10-16, 32 logical CPUs): in the IL2CPP phase, not in Gradle.
  - First `il2cpp.exe` converts IL to C++ in one process, 7.9-8.1 GB: it runs on .NET 8 with Server GC (`il2cpp.runtimeconfig.json`: `"System.GC.Server": true`; UnityLinker too), one GC heap per logical CPU.
  - Then Unity's Bee compiles the C++ with one clang per logical CPU (31-32, ~0.25 GB each, 7.4-7.9 GB in all). The editor holds 2.5-2.8 GB throughout; the Gradle phase takes 6.5-9 GB (its JVM 3.2-3.8 GB).
  - Peaks: 13.4 GB headless, 11.5 GB with `-nographics`; the AABs were identical (same `libil2cpp.so`).
- **`DOTNET_gcServer=0`** in the environment that starts Unity (Bee and il2cpp inherit it; Unity's own Mono ignores it): il2cpp 8.07 → 2.41 GB, UnityLinker 1.0 → 0.65 GB, IL2CPP phase 195 → 192 s, the same AAB. A .NET process that overlapped the conversion (1.9-2.6 GB) dropped to 0.3 GB. The peak then sits on the parallel clangs (11.1-11.2 GB on 32 logical CPUs). Set it for Android builds and iOS exports (the same conversion).
- No effect: `--jobs=8` through `IL2CPP_ADDITIONAL_ARGS` reached il2cpp (it was in Bee's response file) but changed neither its memory nor the clang count: in Unity 6.3 il2cpp only converts and Bee compiles the C++. A Bee parallelism setting wasn't found.
- Both peaks grow with the logical CPU count (GC heaps, clangs): a smaller machine peaks lower. Measure your own over the whole process tree, processes keyed by PID and start time (Windows hands dead compilers' PIDs to other programs: a PID-only sampler summed 17-21 GB of strangers), e.g. a project's `docs/ai/araclar/surec-tepesi.ps1`, and size heavy-job tickets by it.
- Gradle: Unity starts the daemon with `-Dorg.gradle.jvmargs=-Xmx<n>m` from *Preferences › External Tools › Maximum JVM heap size* (default 4096 MB), so Gradle's own default (`-Xmx512m -XX:MaxMetaspaceSize=384m`) and a generated `gradle.properties` don't decide it; never lower it without a measured peak (R8 can run out of memory). Unity runs `gradle --stop` at the end of every Android build, which stops every daemon under the same Gradle home: another Android build running there dies "Gradle build daemon has been stopped: stop command received". Start every Unity process that builds Android with its own `GRADLE_USER_HOME` (one per project; the first build downloads the dependencies once). Never stop Gradle daemons by hand.
- One ABI per build: each extra ABI repeats the whole C++ compile. Store build ARM64; an x86_64 check build separately.

## Store builds
- Projects using Unity Services: an earlier batchmode build lacked the Services project ID (with no access token `CloudProjectSettings.projectId` was empty although `PlayerSettings.cloudProjectId` was set; the build's `UnityServicesProjectConfiguration.json` had no `com.unity.services.core.cloud-project-id` → Authentication and Remote Config failed at runtime). Project E 2026-10-15 (Services Core 1.18) built its store AAB headless and Remote Config worked: the id sits in `globalgamemanagers`, and a missing `com.unity.services.core.cloud-environment` key only means production (it switches Authentication and IAP to staging URLs; the editor writes it from its `-cloudEnvironment` argument). So build headless and check the bundle: `unzip -p <aab> base/assets/bin/Data/globalgamemanagers | grep -c -a <cloudProjectId>` ≥ 1, then Remote Config or sign-in on a device; id missing → the signed-in GUI editor.
- Headless build signed with a custom keystore, passwords never in a file or in a command Claude runs: the **user** starts the editor from their own PowerShell with the passwords only in its environment (`$env:X`, `Start-Process`, `Remove-Item Env:X`); Claude's eval sets `PlayerSettings.Android.keystorePass`/`keyaliasPass` from `Environment.GetEnvironmentVariable` and clears them after the build. Unity still writes them into `Library/Bee/Android/Prj/IL2CPP/Gradle/launcher/build.gradle` (ignored), as in any signed build. The user tests candidate passwords first without changing anything: `keytool -list -storepass:env S`, then `keytool -certreq -alias <a> -storepass:env S -keypass:env K -file NUL`. Default remains the release split: the user types them into the open editor. (Project B 2026-10-08.)
- A player build saves PlayerSettings changed in memory: a custom keystore switched off for a debug-signed check build was written as `androidUseCustomKeystore: 0`. Restore after the build, run `AssetDatabase.SaveAssets()`, confirm `git diff ProjectSettings/ProjectSettings.asset` is empty.
- Right after `switch_build_target` the first `unity command build` returned HTTP 400 although its dry run was valid; a retry queued. Wait a few seconds after a target switch.
- `BuildReport.summary.totalSize` isn't the Android package's size (2026-10-17: 766.7 MB for a 53.2 MB APK): report the output file's own size.
- EDM4U and TextMesh Pro rewrite some tracked files with LF (`GeneratedLocalRepo`, TMP font assets, `mainTemplate.gradle`); with `core.autocrlf=true` git lists them as modified while `git diff` is empty. `git add` on them refreshes the index; nothing gets committed.

## Emulator checks of a release build
- An x86_64 emulator running the ARM64 build through translation: with Optimized Frame Pacing on, the release build crashed in Swappy about 1 s after launch (2026-10-17: `SwappyDisplayManager.nSetSupportedRefreshPeriods`, "berberis: Cannot process signal 11"; forcing GLES didn't help; Project B crashed there earlier). Smoke-test a variant with it off (its own build method); the store build keeps its setting.
- Logcat checks such as "no Firebase before consent": other apps also log with Firebase's tags (FirebaseApp, FirebaseInitProvider, FA, FA-SVC: Play services, Messages, Safety Hub), and Play services logs the game's own events in its process (FA-SVC). Filter by the game's pid or its package name, never by pid alone (one project's `Tools/Emulator/kvkk.py` › `ours()`).
- Git Bash rewrites an argument that starts with `/` into a Windows path before a native program sees it: `adb pull /sdcard/x.csv` failed "failed to stat remote object" (Project C 2026-10-17). Prefix `MSYS_NO_PATHCONV=1` for `adb shell`, `adb pull` and any remote path.
