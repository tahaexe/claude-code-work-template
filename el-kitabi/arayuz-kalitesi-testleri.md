# UI test list

Rule: everything measurable is an automated test that fails the run; only taste stays manual (§3 and the honest side-by-side, arayuz-kalitesi.md §5). A release needs a green run on the whole matrix in both languages, plus the honest review.

## 1. Screen matrix
- **Profiles** (portrait; landscape games swap width and height, move the top inset to both the left and the right edge and test both rotations; the bottom keeps the home indicator or gesture bar, and the 3-button nav bar moves to a side edge). Density = device pixels per dp/pt; for minimum-size checks the strict (higher) density is used. Insets = unsafe pixels at top / bottom (edge-to-edge on Android 15+).
  | Profile | Pixels | Density | Insets top / bottom (px) | Why |
  |---|---|---|---|---|
  | android-small | 720x1280 | 2.0 | 48 / 96 | old small phone, 3-button nav: worst case for text and touch |
  | android-16x9 | 1080x1920 | 3.0 | 72 / 144 | Play store screenshots (Play rejects a long side > 2× the short side) |
  | android-20x9 | 1080x2400 | 2.625 | 136 / 63 | most current Androids (Pixel 6-8 are 420 dpi): the status bar matches the punch hole (128-136 px), gesture bar 24 dp |
  | android-21x9 | 1080x2520 | 2.625 | 136 / 63 | tallest common phone (one project already tests it) |
  | iphone-375pt | 750x1334 | 2.0 | 40 / 0 | iPhone SE: the strictest iPhone |
  | iphone-6.9 | 1320x2868 | 3.0 | 186 / 102 | Dynamic Island; App Store 6.9" set (1290x2796 also accepted) |
  | iphone-6.3 | 1206x2622 | 3.0 | 186 / 102 | App Store medium iPhone set |
  | ipad-13 | 2048x2732 | 2.0 | 48 / 40 | App Store 13" iPad set |
  Sources: AOSP device configs (Pixel densities, status bar = cut-out height), Android insets (gesture bar 24 dp, 3-button bar 48 dp); iPhone and iPad values are simulator measurements (Apple no longer publishes the table): Dynamic Island phones 62 pt top and 34 pt bottom in portrait, 62 pt left and right with 20 pt top and bottom in landscape (iOS 26); SE 20 / 0; iPad 13" 24 / 20. Keep the table in one place (the harness's `DeviceProfiles`, arayuz-test-duzenegi.md) and correct it there when a device check disagrees.
- **Store shots:** sets and sizes in store-listing-optimization.md › Limits (Play's long side ≤ 2× the short side, so never 1080x2400; App Store 6.9" and 6.3" iPhone sets plus iPad 13").
- **Languages:** tr and en (and every shipped language).
- **States per screen:** default; longest text (real tr; en pseudo-localised +40%); biggest numbers (9.999.999 coins, 99 boosters); empty (0 coins, no boosters); every popup in the queue; reduce motion on; sample store prices in other currencies ("1.234,99 ₺", "€4,99", "R$ 24,90", "₹449", "¥800", "₩5,500").
- **Capture:** PlayMode in batchmode with a GPU. Each canvas switches to Screen Space - Camera on a render texture at the profile size (Overlay canvases never reach a camera capture), the safe area and density come from the injected provider (arayuz-test-duzenegi.md). Name: `Logs/claude/screens/ui-matrix/<screen>-<state>-<lang>-<profile>.png` plus `report.json` (one record per failure: screen, state, lang, profile, check, gameObjectPath, value, threshold, shotPath). Sheets per screen with cift.py for review.

## 2. Automated checks (each fails with the object's path, profile and language)
| # | Check | Rule | How (Unity 6000.3) |
|---|---|---|---|
| 1 | Text fits | no TMP text overflows or truncates; each label within its max line count (buttons: 1) | after `ForceMeshUpdate()`: `!isTextOverflowing` (vertical only) `&& !isTextTruncated` (truncate/ellipsis) `&&` text bounds inside the rect minus margins (±0.5 px); the bounds test also catches no-wrap overflow (don't use `preferredWidth`: under auto-size it is computed at `fontSizeMax`). `maxVisibleLines` defaults to 99999, so use a per-label rule (`UiTextRule.maxLines`) |
| 2 | Glyphs | every visible character comes from the label's font or its allowed same-face fallbacks; TMP Settings' global fallbacks and LiberationSans never count | runtime: after `ForceMeshUpdate`, each visible `textInfo.characterInfo[i].fontAsset` is in the allowed set, and the static event `TMP_Text.OnMissingCharacter` never fires (it fires even with TMP warnings off); static: every localized string through `HasCharacters(text, out uint[] missing, searchFallbacks: false, tryAddCharacter: false)` per allowed asset, which must be Static (dynamic assets only on the runtime path: their unrasterised glyphs read as missing); include the price samples |
| 3 | Text size | body ≥ 14 dp, button labels ≥ 18 dp, titles ≥ 24 dp, nothing < 12 dp (legal ≥ 11); `fontSizeMin` of auto-sized labels ≥ the same floor, converted per profile | em span in px = `|WorldToScreenPoint(cam, tf.TransformPoint(p + Vector3.up * characterInfo[i].pointSize)).y − WorldToScreenPoint(cam, tf.TransformPoint(p)).y|` (any local point p, cam = the capture camera), divided by the profile density; never the glyph's own box (cap height), never `Screen.dpi`, never `fontSize × lossyScale × scaleFactor`. Role: `UiTextRule`, else Button under a Selectable and Body elsewhere; titles must be tagged |
| 4 | Touch size | every interactable hit area ≥ 48 dp on every profile; neighbours ≥ 8 dp apart, measured between hit rects after padding | the union of the raycast-target Graphics whose click handler is the control (non-drawing ones included), each rect grown by −`raycastPadding` (left, bottom, right, top) → screen px → / density |
| 5 | Touch reach | the centre and 4 inner edge points of each hit area reach that control | `EventSystem.current.RaycastAll`; the first result's handler is the control (a project's touch-measuring eval) |
| 6 | Safe area | every interactable and text rect inside the profile's safe area; only backgrounds and dimmers outside | rect vs. the injected safe rect; static scan: no `Screen.safeArea`, `Screen.width`, `Screen.height`, `Screen.dpi` outside the screen provider |
| 7 | Contrast | text ≥ 4.5:1; large text (≥ 24 dp, or ≥ 18.5 dp bold) ≥ 3:1; icons and component edges needed to identify a control ≥ 3:1 | render the state once with every TMP hidden by `tmp.CrossFadeAlpha(0f, 0f, true)` (it reaches the `TMP_SubMeshUI` children that draw fallback glyphs such as our Turkish ğ ı ş İ; `canvasRenderer.SetAlpha(0)` doesn't; restore with 1f), sample the background under each glyph quad (worst 10th percentile), text colour = `color × faceColor` (vertex-gradient min and max), alpha-composited; WCAG luminance with the 0.04045 threshold. Wide outline (≥ 1.5 dp): fill vs. outline ≥ 4.5:1 and outline vs. background ≥ 3:1; thinner: outline is part of the letter. Icons: sprite pixels vs. the ring around them. GPU only (`Assert.Ignore` when `SystemInfo.graphicsDeviceType == Null`) |
| 8 | Colour-blind | meaningful game colours pass renk-korlugu-palet.md | `el-kitabi/araclar/cvd_palette.py` on the palette; CVD simulation on shots (Project F) |
| 9 | Roles | exactly one `Primary` per state and it is the largest interactable (area ≥ 1.3× the next); each `Rewarded` shows an allowed video icon and a number; each `Purchase` shows the store's price string; red only on `Destructive`; `Close` hit area ≥ 48 dp | `UiRole` component (Primary, Secondary, Rewarded, Purchase, Destructive, Close) walked over the tree; video icon by sprite name list; number by regex on the child labels; prices: inject each §1 sample through the project's price provider (a catalog hook) and expect it verbatim; "red" = `Graphic.color` × the sprite's mean colour with hue 345-15° and saturation ≥ 0.5 |
| 10 | No placeholders | no visible "New Text", "Text", "Button", "Lorem", "TODO", default Unity sprites (UISprite, Background, Knob), magenta material, LiberationSans | walk active canvases: strings, sprite names, font asset names |
| 11 | Motion timing | popups open in 0.2-0.3 s, result panels within 0.15 s with their content still by 1.2 s; close 0.12-0.2 s; press 0.08-0.12 s; last move → win panel ≤ 0.6 s, or every longer chain skippable with a visible "tap to skip"; win primary interactable ≤ 1.2 s after open; lose Retry ≤ 0.7 s after the title; UI tweens on unscaled time | read declared durations and eases from the project's motion wrapper (`UiMotion`); if measured, real time with ±50 ms tolerance (parallel agents load the CPU); run once at `Time.timeScale = 0` and assert that panels still open and the primary becomes interactable within the same limits; `DOTween.safeModeLogBehaviour = SafeModeLogBehaviour.Error` in tests |
| 12 | Reduce motion | with the switch on, opening and settling a screen changes only alpha; counters jump; particles off or reduced; the first-launch default follows the OS flag | record `localScale`, `localRotation`, `anchoredPosition` of every RectTransform under the panel each frame through open and settle (scroll content and tagged exceptions excluded); the native reader behind an interface, unit-tested with fakes |
| 13 | Flashes | no more than 3 flashes in any second (WCAG 2.3.2) | sliding 341x256 windows (a 10° field at 1024x768, scaled to the profile); a transition = ≥ 25% of the window's pixels change relative luminance by ≥ 0.1 with the darker side < 0.8; a flash = two opposing transitions; sample at 60 Hz (`Time.captureDeltaTime = 1f/60`, check unscaled tweens follow it); red flashes counted separately |
| 14 | Frame rate | `Application.targetFrameRate == 60` on mobile (Unity's mobile default is 30) | PlayMode: load the boot scene, assert |
| 15 | Garbage | UI per-frame code allocates nothing | `Assert.That(() => hud.Tick(), Is.Not.AllocatingGCMemory())` around counters, timers and HUD updates (Project A's pattern); whole frames at 0 B only on a development build on a device (ProfilerRecorder); editor frames include editor allocations |
| 16 | Canvas cost | an idle screen dirties no Graphic and moves no RectTransform every frame, unless under its own nested Canvas; `Canvas.pixelPerfect` off where anything moves | `Graphic.RegisterDirtyVerticesCallback` / `RegisterDirtyLayoutCallback` / `RegisterDirtyMaterialCallback` counted over 300 idle frames; `transform.hasChanged` reset every frame and never set on consecutive idle frames (tweens and Animators re-batch the whole canvas without dirtying a Graphic) |
| 17 | Assets | UI sprites in an atlas, ASTC, mipmaps off; texel density 0.75-2.0 at the largest profile; font atlases ≤ 2048 and one page after all strings shown; no TMP material instances; only the GUI Pro files the screens use; APK delta reported | importer checks; `SpriteAtlas.CanBindTo`; `fontMaterial` "(Instance)" scan; a project's size-measuring eval |
| 18 | Strings | no user-facing literal in scenes or prefabs; no TMP UpperCase, LowerCase or SmallCaps style on localized labels (they follow the phone's culture, TMPB-188); Turkish casing with tr-TR; numbers with the language's culture (tr-TR 1.250,5); no Turkish plural after a number (warning) | scan serialized texts against the string tables (the catalog names the project's localized-text component when it doesn't use Unity Localization); style flag scan; unit tests for the casing and number helpers (run them under an English and a Turkish `CurrentCulture`); a regex over the tr table for a number placeholder followed by a word ending in -lar/-ler (`\{\d+\}\s+\w+(lar|ler)\b`) |
| 19 | Polish proxies | every popup has a full-screen dimmer (alpha ≥ 0.7; leaders ~0.78) behind it; the dialog surface is ≥ 1.3:1 lighter than the dimmed scene or has a light rim; empty area inside a dialog ≤ 40%; a win state fires a celebration ≤ 0.3 s after the panel opens (+50 ms); on phones the primary is ≥ 64 dp tall and ≥ 50% of the width when alone (leaders 52-64%), ≥ 39% each when two share a row (home: Royal Match 41-42% each); on tablets at least its phone size in dp; the background is not one flat colour (warning) | tree: dimmer Image rect and alpha; pixels: surface vs. scene; union of child rects vs. the panel's content rect; `UiMotion.Celebrate` or a ParticleSystem playing; background region luminance range (warning only) |
| 20 | Hygiene | raycastTarget off on decorative graphics; nested LayoutGroup depth ≤ 2 and no LayoutGroup + ContentSizeFitter fight on one object; ≤ 2 full-screen semi-transparent images per state; alpha-0 hit images use `cullTransparentMesh` or a non-drawing Graphic; ≤ 30 UI batches per state (the catalog may override with a reason); exactly one EventSystem with `InputSystemUIInputModule`; every Selectable has press feedback and a sound; RectMask2D rather than Mask for rectangles | tree walk; batches on the UI-only render (`UnityStats` in the editor, as Project F does); press feedback = the project's press component or `transition != None`, sound = its click-sound component (both type names in the catalog) |
| 21 | Back button | Android back (Escape in the Input System) closes only the top popup; never quits from a popup or mid-level | PlayMode per popup state: send Escape, assert the stack |
| 22 | Act once | Continue, Purchase, Rewarded and Claim spend, grant or open exactly once on a double tap and stay non-interactable until resolved | two `ExecuteEvents.Execute(go, ped, ExecuteEvents.pointerClickHandler)` in one frame; count the spends and grants |
| 23 | Haptics | no `Handheld.Vibrate` | static scan of the scripts |

## 3. Device and manual checks (manuel-testler.md)
- On one real Android phone and one iPhone when possible: notch and gesture bar, haptic strength, 60 FPS feel in menus, first launch to first win time, sound balance.
- The 1-second test: show a shot for one second and ask "what do I tap?" The answer must be the primary.

## 4. Honest review
- The side-by-side sheet with two references and the 1-5 scores (below 4 anywhere → fix before sending; scores in the plan's closure): arayuz-kalitesi.md §5.
