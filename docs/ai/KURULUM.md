# Install and Template Update
<!-- Read only when installing or updating. -->

**Template folder:** the folder containing the `docs/ai/` you read this from. Reading it inside the project means the template files are already copied; for add-ons (`eklentiler/`) take the template folder path from the global CLAUDE.md, else ask the user.

## Kurulum (Install)
1. **Project type:** detected (e.g. `ProjectSettings/ProjectVersion.txt` → Unity) → say it and go on; else one question with options: **Unity** · **Diğer**. With **Unity** the rest runs automatically: return to the user only where these files say "ask" or "get approval". Unity chosen but no Unity project in the folder → first run `eklentiler/unity/KURULUM-UNITY.md` → "Yeni proje (New project)" in the template folder; install then continues from step 2 in the new project folder.
2. **Copy files:** the template's `docs/ai/` into the project's `docs/ai/`. Never overwrite an existing file (Git Bash: `cp -rn`; PowerShell: `robocopy <src> <dst> /E /XC /XN /XO`).
3. **Git and settings:** not a git repo → `git init` and a fitting `.gitignore` (Unity's standard one for Unity); tell the user. Step commits depend on it. **`.gitignore`** (new or existing): append only missing lines, never remove one. Every project: `.vscode/`, `.idea/`, `.vs/`, `.claude/settings.local.json`, `.claude/worktrees/`, `Thumbs.db`, `desktop.ini`, `.DS_Store`. Unity also: `*.slnx` and missing lines of Unity's standard `.gitignore`, taken live (`gh api repos/github/gitignore/contents/Unity.gitignore -H "Accept: application/vnd.github.raw"`), not from memory (solution and project files are ignored only in Unity; elsewhere they are source). A line the project left out on purpose (a recorded decision) stays out. Tracked files under these patterns that editors or builds recreate → `git rm --cached` (they stay on disk; other machines drop their copy on the next pull, editors recreate them); vendor files no tool recreates (third-party folders) stay tracked; tell the user in one line. **`.gitattributes`** (new or existing): append `*.sh text eol=lf` if missing, never remove a line (with `core.autocrlf=true` a fresh clone checks `.sh` files out with CRLF and bash fails on the `\r`); `.sh` files already CRLF on disk → convert them (`sed -i 's/\r$//' <file>`). `.claude/settings.json` stays tracked. No `.claude/settings.json` → create it from `docs/ai/sablonlar/claude-settings.json`; otherwise add only missing entries to `permissions.allow`, `enabledPlugins`, `env`, `skillOverrides`, `attribution` and `autoMemoryEnabled`, never touching existing values. These settings cost no context: Claude's local auto memory is off, so all memory stays in `docs/ai/` and git carries it between machines; step commits and their push need no approval; Claude in Chrome tools run without prompts (page JavaScript follows the permission mode); commits carry no co-author line or session link; plugins that conflict with the protocol (superpowers, plugin-dev) and `/batch` (worktree and PR fan-out) are off; unity-perf skills are hidden; helper agents can't spawn agents. **Plugins** (user scope; silently if the global CLAUDE.md marks this as the template owner's computer, else ask once): never install agent-protocols or engineering; `agent-protocols@agent-protocols` or `engineering@knowledge-work-plugins` enabled in `claude plugin list` (desktop-app copies too, e.g. `agent-protocols@synced`) → `claude plugin disable <plugin> --scope user` (or `false` under `enabledPlugins` in the user settings), with one line to the user why: agent-protocols' SessionStart hook emits invalid JSON on Windows, and both plugins' skills went unused (engineering also brings unconnected MCP servers). `unity-perf@gqy-plugins` (`tianzhiying/unity-perf`) in any scope → `claude plugin uninstall`, `claude plugin marketplace remove gqy-plugins`, drop its settings entries. Owner's computer: `superpowers@claude-plugins-official` on at user scope → set it `false` in `~/.claude/settings.json` (its hook makes skill use mandatory). A GitHub SSH "host key" error on a plugin install → run it with `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=url.https://github.com/.insteadOf GIT_CONFIG_VALUE_0=git@github.com:`. Plugin changes apply from a new session.
4. **Inspect the project** (one helper agent for the broad scan): engine/framework and version, languages, folders, build/test/run commands, code conventions (lint/format config, README, old CLAUDE.md, AGENTS.md, .cursorrules …), git state and main branch.
5. **CLAUDE.md:** missing at the project root → create it from `docs/ai/sablonlar/CLAUDE.sablon.md` and fill it (terse English). Existing → move its content into the new structure without losing anything (translate to English); ask the user about old workflow instructions that conflict with the protocol. ≤160 lines and ≤10,000 characters, only what every task needs. Never invent a command or rule: mark it `‹?›` and ask.
6. **Engine add-on:** Unity → read `eklentiler/unity/KURULUM-UNITY.md` in the template folder and apply "Kurulum (Install)". Don't rewrite in step 7 the rules the add-on installs.
7. **Project rules:** rules valid only for certain file types or folders go to `.claude/rules/<topic>.md` (English), with `paths:` so they load only when matching files are read:
   ```markdown
   ---
   paths:
     - "src/**/*.ts"
   ---
   # TypeScript rules
   - …
   ```
   Base rules on observed facts: generated files not to hand-edit, folders not to touch, required patterns. A rule loads when a matching file is *read*, not when one is created; a YAML error makes it load every session. Rules for every task stay in CLAUDE.md.
8. **Start memory:** unless the project is small, write `docs/ai/hafiza/mimari.md` (≤60 lines: main systems, folders, entry points, data flow) and index it in `HAFIZA.md`. Pitfalls noticed while inspecting → `dersler.md`. Fill **Updated** in `DURUM.md`. **Local notes:** the project's auto-memory folder on this machine (`~/.claude/projects/<project path, each non-alphanumeric character as '-'>/memory/`, e.g. `C:\Games\My_Game` → `C--Games-My-Game`) holds notes → move every fact into `hafiza/` (`kararlar.md`, `dersler.md` or a topic file indexed in `HAFIZA.md`); after this run's commit delete that folder and tell the user in one line. With auto memory off (step 3) nothing there is read again.
9. **Handbook:** read only the front matter of the template's `el-kitabi/` entries (not `NASIL.md`). Copy entries whose `condition` holds into `docs/ai/el-kitabi/` (the tools their `requires` names from `el-kitabi/araclar/` into `docs/ai/el-kitabi/araclar/`) and list each in `HAFIZA.md`'s one handbook line (`` `el-kitabi/` (open the entry whose hint fits the task; unsure → read its front matter): `<name>` (the tasks of its `read_when`, 3–8 words) · … ``; create it if missing), unless an always-loaded file already routes to it (e.g. PROTOKOL §1 → `tarayici-baglantisi.md`, §3 → `on-arastirma.md`, `proje-kontrol-listesi.md`, §4 → `kalite-kapisi.md`; CLAUDE.md's Unity section → `unity-cli-saha-notlari.md`, `unity-derleme-ve-bellek.md`, `csharp-lsp.md`): such an entry gets no hint; leave the rest. Each `plan_candidates` item → one line in DURUM's **Up next**, unless the work is already done or an exemption in the entry clearly applies. A tool in `requires` is missing → offer to install it: install or give the steps if the user agrees; otherwise skip, record the decision in `hafiza/kararlar.md` and never ask again.
10. **Review:** summarize CLAUDE.md, the rule files and any add-on setup to the user (Turkish, briefly); apply their corrections.
11. **Commit and push** (push if a remote exists): `chore: set up Claude working system`. `docs/ai/` is tracked by git; if `.gitignore` excludes it, tell the user.
12. **Introduce** (Turkish, 3-4 sentences): normal talk is enough, big tasks become plans, plans and memory live in `docs/ai/` (Claude's files in English; manual tests and design docs in Turkish). If **Up next** has items, propose the first as the first plan (a new game or channel project starts with the pre-research, PROTOKOL §3). Settings apply from a new session: suggest one `/context` there (core files visible; no superpowers, plugin-dev, agent-protocols or engineering skills).

## Güncelleme (Update)
1. Note the project's version (PROTOKOL line 2; step 5 needs it), then copy **only** these fixed files from the template (overwrite): `PROTOKOL.md`, `KURULUM.md`, `BAKIM.md`, `araclar/`, everything in `sablonlar/`. `manuel-testler.md` only if missing (then index it in `HAFIZA.md`). Add the missing rules and settings of `sablonlar/claude-settings.json` to `.claude/settings.json` as in Install step 3; values still at an old template default follow the new template (1.18: `git push` rules leave `permissions.ask`; 1.33: the force-push rules leave `permissions.deny`, `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` leaves `env`, `simplify` leaves `skillOverrides`; 1.35.1: `deniedMcpServers` leaves; 1.55: the `agent-protocols:*` and `engineering:*` keys leave `skillOverrides`). A relaxation refused in auto mode (classifier) → leave it and give the user the exact lines to delete by hand. Run Install step 3's `.gitignore`, `.gitattributes` and plugin checks (turns agent-protocols and engineering off, removes unity-perf, turns superpowers off on the owner's computer) and Install step 8's local-notes move too (each machine's notes move on that machine). New settings or plugins → suggest one `/context` in a new session.
2. **Never touch:** `DURUM.md`, `HAFIZA.md`, `hafiza/`, `planlar/`, `manuel-testler.md`, `tasarim/`, the project's CLAUDE.md. A plan written before 1.57 (one file with its Progress log, no step files) runs to its end in that format, its older log entries still moving to `planlar/arsiv/<plan-name>-log.md` past ~15,000 characters; the next plan uses the index and step files. Exceptions: step 1 (local notes move into `hafiza/`), steps 3–4 (CLAUDE.md structure, Unity section), step 5 (handbook line and plan candidates are added or updated; the one-time 1.36 shortening) and step 6 (one-time English migration).
3. Compare the new `sablonlar/CLAUDE.sablon.md` with the project's CLAUDE.md; apply structural differences (e.g. a new `@` line) and tell the user.
4. **Add-on:** the project has `.claude/agents/unity-uzmani.md` or `.claude/rules/unity-*.md` → also apply `eklentiler/unity/KURULUM-UNITY.md` → "Güncelleme (Update)" in the template folder.
5. **Handbook:** replace installed entries and their tools with their new template versions, keeping notes the project added (lines missing from that entry or tool at the project's old version: `git show v<old>:el-kitabi/<file>` in the template folder; e.g. `r8-kontrol.py` allowances); tell the user they can go to the template. An installed entry's `plan_candidates` changed → replace their old lines in **Up next** and add the new ones (not for work already done). Add new entries whose condition now holds as in Install (`HAFIZA.md` handbook line and `plan_candidates` included); an entry's `read_when` changed → refresh its hint. Once (1.36): HAFIZA's one line per entry → the one handbook line, and `docs/ai/` drops from HAFIZA and DURUM paths; check with `kayip-kontrol.py` (facts and clauses). Once (1.51): hints for entries an always-loaded file routes to (Install step 9) leave the handbook line. Tell the user about added or changed plan candidates; never re-offer a declined tool.
6. **One-time English migration** (Claude's files still Turkish, i.e. projects from before 1.14): tell the user in one Turkish line what will be translated and that the originals stay in git history; get a yes. Then one file at a time: CLAUDE.md, `DURUM.md`, `HAFIZA.md`, `hafiza/*.md`, project rules in `.claude/rules/`, plans in `planlar/` (not `planlar/arsiv/`, `tasarim/` or `manuel-testler.md`):
   - Commit pending changes first.
   - Rewrite entry by entry as terse English bullets; keep every fact: names, paths, commands, numbers, dates, causes, user decisions with their dates. Never merge distinct entries or drop a "why".
   - Meet the size limits by moving detail, never by deleting it: DURUM detail → plans or `hafiza/`, tech debt → `hafiza/teknik-borc.md`, long CLAUDE.md details → a `hafiza/` file plus a one-line pointer.
   - Run `python docs/ai/araclar/kayip-kontrol.py --rev HEAD --facts-only <old and new files>` (a translation changes every word, so no clause check); restore every real fact it reports (labels that were only translated may stay).
   - Commit: `docs: translate <file> to English (lossless)`.
7. **Commit and push** (if git; push if a remote exists): `chore: update Claude working system to v<version>` (version on line 2 of `PROTOKOL.md`). Before the push count `git rev-list --count @{u}..HEAD`; commits older than this update go out too → tell the user how many.
